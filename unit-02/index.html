        Explain the result
        
MOV copies a value and preserves arithmetic flags. ADD changes EAX to 8 while EBX stays 3. SUB changes EAX to 0 and sets ZF. Fetch/decode/execute are conceptual stages, not individual clock cycles. Real CPUs overlap these activities.

The byte display is a register value written most-significant byte first; it is not a memory layout. A 32-bit write clears the upper 32 bits (zero-extension). An 8-bit or 16-bit write preserves bits outside the selected alias. MOV does not change arithmetic flags.

      
AH, BH, CH, and DH name the high byte of AX/BX/CX/DX. They cannot be encoded in any instruction that also requires a REX prefix (for example, one using R8–R15 or a 64-bit operand size) — on real x86-64 hardware that combination is illegal, so this model never asks you to mix AH-style high-byte registers with a REX-requiring operand.

CF reports an unsigned carry (ADD) or borrow (SUB). OF reports that the mathematical signed result does not fit. ZF tests for a zero result; SF is the result’s top bit. AF reports a low-nibble carry/borrow. PF checks even parity in the low byte only.
