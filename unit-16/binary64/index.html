Binary64 representation and rounding

Predict the stored representation, reveal exact bits, and compare neighboring values.

A representation explorer, not an SSE2 emulator. DataView extracts the 64 stored bits. BigInt arithmetic gives exact rational and decimal values for finite encodings. Decimal input and addition use JavaScript binary64 arithmetic; typed decimal text is not assumed exact. No code execution, file access or network requests.

1. Choose an observation

Decimal mode accepts a sign and exponent notation, or Infinity, -Infinity, NaN. Overflow/underflow during conversion is visible in the resulting classification. Hex mode requires 16 digits. These exploration inputs are broader than the lecture adapter’s two-decimal grammar.

4. Neighbor spacing

“Down” and “up” mean the next numerically smaller/larger representable value, not a decimal increment. The two gaps can differ at powers of two. Here ULP spacing is stated separately on each side; no universal epsilon is implied.

For either zero, next up is the smallest positive subnormal and next down the smallest negative subnormal. At infinity, one direction stays infinity. NaN has no ordered neighbors.

5. Comparison and display

For UCOMISD-style comparison with a quiet NaN, check unordered (JP) before equality (JE): ZF is also set for unordered. This models result flags, not signaling-NaN exceptions, MXCSR traps or every SSE2 instruction. Positive and negative zero compare equal.

Lecture adapter’s two-decimal output:

The adapter accepts only finite magnitude ≤1,000,000 and computes binary64 abs(x)×100, adds 0.5, then truncates to integer cents. Rounded zero has no minus sign. This is not exact decimal financial rounding: stored 1.005 can display 1.00; exact 0.125 displays 0.13. Display formatting does not modify the bits above or the value used by arithmetic.
