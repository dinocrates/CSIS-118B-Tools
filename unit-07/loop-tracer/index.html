What changes on each iteration?

Predict the work, then trace initialization, conditions, body, update and termination.

This bounded teaching simulation follows the three counted-loop lesson programs. It groups instructions into meaningful phases; it does not assemble arbitrary code, emulate every register, or execute console helpers. Counts are limited to 0–10, with exact integer state and at most 44 trace steps.

3. Check the prediction

Explain why it stops

  • Countdown: R12 holds repetitions remaining. The zero guard bypasses the body. After each Hello, DEC consumes one repetition and JNZ immediately uses its fresh ZF. Never remove the zero guard.
  • Count-up: R12 is the limit and R13 starts at 1. JG exits only when current is greater than N. Equality still runs the body; JGE removes that endpoint.
  • Accumulator: R14 starts at zero once. At each condition check it contains the sum of all processed integers, from 1 through current − 1. N = 0 yields an empty sum of zero.

Course helpers preserve R12–R14. Other working registers and flags may change during calls. These examples retain live state in preserved registers and create fresh flags immediately before the branch that uses them. The small bound keeps the largest sum at 55; this tool does not model overflow or an unsafe unbounded loop.
