Virtual file cursor explorer

Predict a syscall result, reveal it, then apply one operation.

Teaching simulation, not the playground runtime. One synthetic file, at most 32 bytes and four open descriptors. No host filesystem, permissions prompt, network request or NASM execution. Counts and indices are bounded exact integers. Standard descriptors 0/1/2 are not simulated; use the descriptors returned by Open.

Each preset resets descriptors, buffer and history. The path is fixed: lesson.bin. Descriptor numbers 3–6 are illustrative allocations; a real program must use the returned value.

    Connect this to NASM

    The initial five-byte sample matches the lesson audit: reading capacity 2 returns counts 2, 2, 1, then 0; values are A/NUL, B/CR, LF. A positive short read is not EOF yet. A zero-capacity read returning 0 does not prove EOF.

    Closing releases a descriptor, not the file. Reopening starts a new cursor at 0. Truncation empties the shared file but does not reset other open cursors. Append places each positive write at the current end, even if another descriptor changed the file. A write beyond the end fills the gap with zeros in this regular-file model.

    A raw read does not append a terminator. Use the actual returned count. To construct a NUL-terminated string, reserve an extra byte and explicitly terminate it; print_string otherwise cannot know the valid length and would stop early on embedded NUL.

    For Linux x86-64 syscalls, RAX selects the operation and receives the result; RDI/RSI/RDX hold the first three arguments. RCX/R11 are clobbered. Preserve needed results before library helper calls and maintain caller stack alignment. This tool models file state only, not registers, memory addresses, call stacks, interruption retries or an entire operating system.

    Actual playground boundary: virtual data files survive rerun/recompile within the loaded playground but disappear on page reload. Source autosave does not preserve those files. This teaching tool also resets on reload and stores nothing. It does not add data upload/download, persistent files or a file explorer to the playground. Multi-source editing is a separate capability; no availability is implied here.
