Where do the arguments go?

Derive register assignments, stack offsets and caller cleanup for one System V AMD64 call.

This fixed simulation models 0–12 ordinary 64-bit integer or pointer arguments. No machine code runs and no pointer is dereferenced. Floating-point/vector arguments, aggregates, variadic calls and hidden arguments are not modeled. The caller starts already aligned, as after P96's main saves R12; earlier frames are outside the diagram.

      Explain the layout

      The first six ordinary integer/pointer arguments use RDI, RSI, RDX, RCX, R8 and R9. Additional arguments occupy successive eight-byte slots. This model reserves the whole outgoing area before CALL, placing any padding above the last argument. It uses no Windows shadow space.

      At callee entry, CALL's return address is at [RSP]. Argument 7, if present, is at [RSP+8]. After PUSH RBP and MOV RBP,RSP, it is at [RBP+16]; argument 8 is at [RBP+24]. Offsets change because the reference pointer moves, not because the argument moves.

      For seven arguments, reserve 16 bytes: the lower eight hold argument 7 and the upper eight are padding. For eight arguments, both slots are arguments. RET removes the return address; the caller removes its outgoing area afterward. Restoring RSP ends that allocation's active lifetime but does not erase its bytes.

      This example has no local storage and no computation body. It restores RBP with POP before RET. A real function must also clean up its local allocation and preserve any other callee-saved registers it changes. A return value would have its own contract; this tool does not calculate one. Cleanup here returns to the caller, not process termination; the course exit helper does not return.
